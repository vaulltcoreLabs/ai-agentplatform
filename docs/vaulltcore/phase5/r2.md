# Phase 5 — Cloudflare R2 Object Plane

**Adapter:** `packages/storage/r2/r2-object-store.ts` — the ONLY file importing
`@aws-sdk/client-s3` + `@aws-sdk/s3-request-presigner`. Uses the S3-compatible API
endpoint `https://${accountId}.r2.cloudflarestorage.com`, appropriate for the
Node/Bun/Fly runtime. A future Cloudflare Worker deployment would implement the same
`ObjectStore` interface over the native R2 binding instead (never both in one path).

**Contract (`ObjectStore`):** `put`, `get`, `head`, `delete`, `exists`,
`createUploadUrl`, `createDownloadUrl`. No listing, no query semantics — it is an
opaque byte store for tenant-scoped keys.

**Security properties (§18, §37):**
- Presigned PUTs bind `Content-Type` into the signature.
- Presign expirations clamped to `[30s, 900s]` (`MIN_PRESIGN_EXPIRY_SEC`,
  `MAX_PRESIGN_EXPIRY_SEC`).
- Credentials read from env once; never logged, never embedded in errors.
- `delete()` is idempotent (R2/S3 DELETE of a missing key succeeds).
- Object keys are server-constructed and tenant-scoped
  (`tenants/{tenantId}/runs/{runId}/artifacts/{artifactId}`).

**Configuration (§12):** `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`,
`R2_BUCKET` (read by `packages/storage/r2/config.ts`). Least-privilege scoped R2
credentials are expected; no account-wide keys required by the code.

**Bucket strategy (§13):** single controlled bucket; tenant isolation is in the KEY,
not in per-tenant buckets. Authorization is enforced by PostgreSQL artifact metadata
(see storage-contract.md). A guessed/forged key without a matching Postgres metadata
row yields no download URL.

**Real R2 gate:** `packages/storage/r2-real-gate.test.ts`.
- Activated by `R2_*` env keys.
- Proves put/head/get/delete/exists, presigned PUT+GET, sha-256 attribution,
  idempotent delete, presign clamping, key isolation on a REAL bucket.
- Without credentials: SKIPPED — missing infrastructure.
